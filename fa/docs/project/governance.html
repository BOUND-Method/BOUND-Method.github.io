حاکمیت

تغییرات را قابل مشاهده، قابل بازبینی و قابل اعتبارسنجی کنید.

حاکمیت BOUND باید همان اصول روش را به‌کار گیرد: مالکیت صریح، قرارداد پایدار، اجرای مستقل و verification پیش از integration.

وضعیت فعلی

repository یک پروژه static GitHub Pages است و این مستندات وجود یک governing body یا استاندارد ratified را ادعا نمی‌کنند.

دسته‌های تغییر

تغییرات موثر بر معنای contract یا artifact باید اثر compatibility و version را روشن کنند.

کنترل تغییر

Contract Freeze یعنی تغییرات قابل مشاهده و تحت حاکمیت باشند؛ به معنی غیرقابل‌تغییر بودن قرارداد نیست.

مالکیت تصمیم

مالکیت domain باید صریح باشد. تغییرات cross-boundary باید ownerها و interfaceهای متاثر را مشخص کنند.

کار آینده

versioning policy، specification status، decision records، maintainer roles و proposal process می‌توانند بعداً اضافه شوند.
