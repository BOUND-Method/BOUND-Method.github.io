مرزهای وب‌سایت

خود وب‌سایت یک نمونه BOUND است.

معماری مستندات به‌صورت domain، boundary، interface و verification target صریح شده است. نقشه ماشین‌خوان آن جداگانه version می‌شود.

چرا این وجود دارد؟

یک سایت روش مهندسی باید همان انضباطی را نشان دهد که آموزش می‌دهد. صریح کردن ساختار، یک test case واقعی برای BOUND می‌سازد.

حوزه‌ها

Method، Guides، Reference، Agents، Research و Project به‌عنوان سطوح محتوایی متمایز سازمان‌دهی می‌شوند.

مصنوعات ماشین‌خوان

نقشه domainها، boundaryها و interfaceها باید مستقل از prose قابل بررسی باشد.

قراردادهای رابط

navigation و cross-domain reference مانند interface عمل می‌کنند و map مشخص می‌کند کدام domain pairها مجاز به ارتباط‌اند.

اعتبارسنجی

CI وجود فایل، JSON syntax، HTML title، لینک محلی، domain path، interface reference و dependency واقعی را با نقشه اعلام‌شده بررسی می‌کند.

این یک representation پیشنهادی است و formal specification، runtime، plugin protocol یا autonomous governance را ایجاد نمی‌کند.
