توسعه یکپارچه مبتنی بر مرز، پرسش معماری نخست را از شکل رابط به مالکیت مسئولیت منتقل می‌کند.

حوزه

پیش از تعریف مرزهای مسئولیت، زمینه سیستم را مشخص کنید: قابلیت، استقرار، اعتماد، ماندگاری، runtime، latency و بازیابی.

مرز

مرز BOUND یک مرز مسئولیت است: چه کسی تصمیم را مالک است، یک مؤلفه چه چیزی را در اختیار دارد، چه تصمیم‌هایی می‌تواند بگیرد، چه چیزی را ارائه و مصرف می‌کند و کدام وابستگی‌ها ممنوع‌اند.

قرارداد

قرارداد رفتار مرزی را برای پیاده‌سازی و اعتبارسنجی مستقل صریح می‌کند؛ از schema و type تا خطا، retry، timeout، ترتیب، concurrency، اعتماد، سازگاری و versioning.

تثبیت قرارداد یعنی تغییر کنترل‌شده. قرارداد می‌تواند تکامل یابد، اما هر تغییر باید تصمیم سازگاری و پیامد مهاجرت مشخص داشته باشد.

اجرا

پس از صریح شدن مسئولیت و رفتار میان‌مرزی، تیم‌ها در محدوده خود مستقل پیاده‌سازی می‌کنند.

اعتبارسنجی

اعتبارسنجی پیوسته است و می‌تواند شامل contract test، بررسی schema و compatibility، integration test، تحلیل ایستا، CI و بررسی runtime باشد.

IFEM → BOUND

IFEM توالی Interface → Contract → Execution → Verification را بنا کرد؛ BOUND همان فلسفه اجرا را با افزودن Domain و Boundary پیش از قرارداد گسترش می‌دهد.
