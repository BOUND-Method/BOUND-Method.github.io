Documentation contracts.

The website declares machine-checkable rules for how documentation pages are classified and what observable evidence they must provide.

Contract model

The contract manifest assigns each documentation surface a document type and claim policy. CI resolves every HTML page to exactly one domain contract and selected pages to a page-level semantic contract.

Contract dimensions

  • Document type: method, guide, reference, example, agent guidance, research, project, or site index.
  • Claim policy: identifies the evidence boundary for the page, such as proposed reference material, illustrative examples, conceptual agent guidance, or research without unsupported results.
  • Required metadata: every page exposes a title and description.
  • Structural markers: selected domains can require observable terms; the method page exposes the complete BOUND lifecycle vocabulary.
  • Semantic content anchors: important pages declare required concepts and required related links. CI checks these after removing shared navigation chrome.

What semantic verification means

A semantic contract does not attempt to prove that prose is true. It verifies that a page contains the documented concepts and relationships expected for its role, making omissions visible during review and CI.

Machine-readable definitions

  • Documentation contract manifest
  • Documentation contract JSON Schema
Scope: the contracts verify documentation structure, semantic content anchors, links, and declared evidence policy. They do not claim to prove every prose statement.
