ROADMAP

From documentation site to verifiable engineering system.

The roadmap is organized around increasing operational depth. Completed items describe work already present in the repository; future items are targets, not commitments to a specific delivery date.

Completed foundation

  1. Documentation information architecture and engineering-focused pages.
  2. Getting Started, boundary, contract, and reference guidance.
  3. Proposed machine-readable artifact schemas.
  4. Practical REST, event-driven, and shared-database examples.
  5. Agent integration, bounded execution, security, and sandboxing guidance.
  6. Research, benchmark-design, and reproducibility guidance.
  7. Project governance, contribution, roadmap, and changelog surfaces.

Next: website as a BOUND reference implementation

  • Define the website's own documentation domains and ownership boundaries in machine-readable form.
  • Represent important documentation contracts explicitly rather than only in prose.
  • Connect each contract to verification evidence and CI checks.
  • Validate navigation, schemas, examples, and metadata as one documentation system.

Agentic engineering phase

  • Specify a durable machine-readable representation for an agent's bounded execution context.
  • Define capability, authority, scope, credential, network, and approval constraints.
  • Define how an agent reports execution evidence and verification results.
  • Explore plugin/tool integration without making an unimplemented runtime or protocol the current architecture.

Research phase

  • Turn proposed benchmark dimensions into reproducible experiments.
  • Publish datasets, environments, raw results, analysis, and limitations where experiments are actually performed.
  • Compare alternative coordination and integration approaches using explicit metrics rather than unsupported claims.

Release discipline

Roadmap status should be updated from repository evidence. A roadmap item is not “complete” merely because it has been discussed or designed; completion should point to an implemented artifact, documented result, or verified repository state.
